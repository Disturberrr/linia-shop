# LINIA — інтернет-магазин одягу та аксесуарів

Український інтернет-магазин (концепт). Мова інтерфейсу — українська, валюта — гривня.
Усі назви, ціни, описи й зображення — демонстраційні; їх змінюють в адмін-панелі.

## Стек

| Шар | Технологія |
|---|---|
| Клієнт | React 19 + TypeScript, збірка esbuild |
| Сервер | Node.js ≥ 22.5 + TypeScript (запуск через `tsx`), власний HTTP-роутер |
| База даних | SQLite (вбудований `node:sqlite`), SQL-міграції в `server/src/migrations` |
| Зображення | `sharp` → WebP у трьох розмірах (400/800/1600) |

Стек успадковано з наявного проєкту й не переписувався на Express/Prisma/PostgreSQL.
SQLite підходить для одного сервера й невеликого навантаження. Для PostgreSQL потрібно переписати шар `server/src/db.ts` і міграції.

## Встановлення та запуск

```bash
npm install
cp .env.example .env     # заповніть SESSION_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD
npm run migrate          # створює базу в DATA_DIR
npm run seed             # тестові категорії, товари, сторінки + адмін із .env
npm run build            # збірка клієнта в dist/client
npm start                # production, http://localhost:3000
```

Розробка: `npm run dev`. Перевірки: `npm run typecheck`, `npm test`.
Адміна без `seed` створює `npm run create-admin`. Публічної реєстрації адмінів немає.
Адмін-панель: `/admin`.

`npm run seed` не чіпає наявний каталог. `npm run seed -- --force` перезаписує його, але відмовляє, якщо в базі є замовлення.

## Змінні оточення

| Змінна | Призначення |
|---|---|
| `PORT`, `PUBLIC_URL` | порт і публічна адреса (sitemap, canonical, OG, платіжні посилання) |
| `DATA_DIR` | де лежать база SQLite та завантажені фото |
| `SESSION_SECRET` | довгий випадковий рядок (`openssl rand -hex 32`) |
| `TRUST_PROXY` | `true` за nginx/Cloudflare, щоб брати IP з `X-Forwarded-For` |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | перший адміністратор |
| `LIQPAY_PUBLIC_KEY`, `LIQPAY_PRIVATE_KEY` | онлайн-оплата LiqPay |
| `NOVAPOSHTA_API_KEY` | довідник міст і відділень Нової пошти |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | сповіщення в Telegram |
| `RESEND_API_KEY`, `NOTIFY_EMAIL_FROM`, `NOTIFY_EMAIL_TO` | сповіщення на email |

Без ключів відповідна інтеграція вимкнена: доступна лише оплата при отриманні, адреса вводиться вручну, сповіщення не надсилаються.

## Що реалізовано

- Головна: hero, категорії, популярні, новинки, акції, переваги, футер. Тексти налаштовуються в адмінці.
- Каталог: фільтри за категорією, ціною, розміром і кольором; сортування, пошук, «показати ще»; стан у URL.
- Сторінка товару: галерея, варіанти, перевірка залишків, «Купити зараз», схожі товари.
- Кошик і обране зберігаються в localStorage. Ціни й залишки перераховує сервер.
- Checkout: контакти, доставка, оплата. Номер замовлення створює сервер, захист від дубліката через ідемпотентний ключ, транзакції.
- Адмін-панель: товари, варіанти й залишки, категорії, фото, замовлення зі статусами, налаштування. Доступ перевіряє сервер.
- SEO: `title`/`description`/Open Graph, JSON-LD для товарів, `sitemap.xml`, `robots.txt`, сторінка 404, `prefers-reduced-motion`.
- Безпека: хеші паролів, обмеження частоти запитів, перевірка завантажених файлів, 27 автоматичних тестів.

## Що потрібно зробити перед публікацією

1. Замінити демонстраційні ілюстрації товарів реальними фотографіями.
2. Перевірити й відредагувати тексти «Доставка й оплата», «Політика конфіденційності», «Повернення». Це шаблони, а не юридичні документи.
3. Вказати реальні контакти, назву та соцмережі в адмін-панелі.
4. Підключити LiqPay (потрібен договір і ключі); без цього онлайн-оплата не працює. Протестувати обробку неуспішних платежів у sandbox.
5. Отримати ключ Нової пошти й перевірити вибір відділень.
6. Налаштувати Telegram або email-сповіщення й перевірити їх.
7. Задати міцні `SESSION_SECRET` і пароль адміна, увімкнути HTTPS, `TRUST_PROXY=true` за проксі.
8. Налаштувати резервне копіювання `DATA_DIR`.

## Обмеження

- Інтеграції LiqPay, Нової пошти, Telegram і Resend написані, але не перевірялися з реальними ключами.
- Сторінки відображаються на клієнті; метатеги й JSON-LD сервер підставляє в HTML. Повного SSR немає.
- Постійного серверного кошика й акаунтів покупців немає: кошик та обране зберігаються у браузері.
- Магазин не готовий до комерційного запуску, доки не виконано список вище.
